# WS5 — Trips: bundled lookup, purpose, connections, edit

> Scoped in `2026-09-05-wingman-v4.md` § WS5. Cites: C1 C3 J2. Add-by-hand landed in WS2; this stream makes it delightful and complete.

## Tasks

1. **`src/providers/flights/`** — `schedule.ts`: a bundled table of the seeded flights (`flightNo`, carrier, from, to, local depart/arrive `HH:MM`, terminals, `overnight`). `resolve.ts`: `resolveFlight(flightNo, date)` → `{ status: 'bundled', segment }` or `{ status: 'unknown' }`, with the degrade chain documented (live → cache → bundled → synthetic → manual; only bundled and manual exist). Pure but async, so a live adapter can drop in later. Tests in `src/providers/flights/resolve.test.ts`; re-add the `src/providers/**/*.test.ts` include.
2. **TripForm prefill** — when the flight number matches and a date is set, from/to/times/terminals fill in and the fields show a "from the schedule" hint; typing over any of them keeps the person's value. J2: `SK1465` + a date is the whole trip for the common case.
3. **Purpose** — Work / Leisure / Both on the form → `Trip.intent.appetite` (the same posture mapping as the profile). Shown on the ticket as a small chip.
4. **Connections** — "+ Add a connection" adds a second `SegmentEntry` whose `from` is the previous `to`; the builder already handles N segments and the layover is computed on add.
5. **Edit** — `#/trip/:id/edit` opens the same form prefilled from the stored trip; Save replaces it (`upsertTrip` via `addTrip`, keeping the id).
6. **Tests** — `resolve.test.ts`, `TripForm.uitest.tsx` (prefill; connection chains), `e2e/add-trip.spec.ts` (type `SK1465` + date → From/To fill; list; the ticket shows the purpose chip).

## Exit

Type `SQ317` + a date and the segment fills in; manual entry works for any airport pair; a connection is one tap; a trip can be edited. `verify`, `lint`, `e2e` green.
