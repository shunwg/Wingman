# WS3 — Circles: setup, admission by list or domain, mark, badges

> Scoped in `2026-09-05-wingman-v4.md` § WS3. This file is the task order for the stream.
> Cites: O1 O3 O4 O5 T1 T3 T5 T6 J4 J10.

**The product sentence.** Every circle surface leads with how people got in. `admissionSentence(rule)` is the one function that writes it, and it appears first on the circle's home, on the invitation, and under the badge.

## Tasks

1. **Domain** — `AdmissionRule` gains `invite_list { emailHashes, salt }` and `any_of { rules }`; `CircleBadge`; `Circle.crestUrl?`, `Circle.badges?`; `CircleMembership.badgeIds?`; `PublicCircleBadge.crestUrl?` / `.badge?`. `domain/admission.ts`: `admits(rule, proof)`, `normaliseEmail`, `admissionSentence`. Tests first (`admission.test.ts`).
2. **Hashing at the edge** — `screens/circles/hash.ts`: `sha256Hex(s)` over `crypto.subtle`; `hashEmail(address, salt)`. Not in `lib/` (the purity gate has no `crypto`).
3. **Redaction carries the badge** — `redact.ts` passes `badgeIds` through as `badgeIds` on the public badge; `state/selectors/circles.ts` decorates public badges with the circle's `shortName`, `kind`, `crestUrl`, and the first badge's `{label, tone}`, from `myCircles ∪ SEED_CIRCLES`. The board selector uses the same decorator.
4. **Seed** — `gridweek` gets `badges: [Organiser, Speaker, Sponsor]`; Priya's gridweek membership gets `badgeIds: ['speaker']`. The `insead` and `northwind` circles are unchanged.
5. **Store** — `createCircle(circle)` also sets `badgeIds: ['organiser']` on the creator's membership when the circle defines that badge; `updateCircle(circle)` for the organiser's edits.
6. **SetupScreen** (`#/circles/new`, replaces NewCircleScreen) — three steps under a `Stepper`: Name & mark → Who gets in → Badges. Finish → `createCircle` → invitation panel with link.
7. **CircleScreen** (`#/circles/:id`) — mark, name, dates, the admission sentence, bucketed members, your badge display toggles (moved here from the list), members you may see (`show_badge` only, as `PersonCard layout="row"`), Leave.
8. **CirclesScreen** — a list: mine first, then discoverable; each row links to the circle's home. Join/locked stays.
9. **JoinCircleScreen** — leads with mark + name + dates + sentence. `invite_list` and `any_of` with a list branch render the email-OTP flow inline (`useVerify` + `ChallengeView`), hash the verified address, and `joinCircle` when `admits()` says yes.
10. **PersonCard** — circle chip = crest (image or two letters) + short name + badge label.
11. **Tests** — `admission.test.ts`, `circles.selector.test.ts` (badge decoration; `match_only` never decorated), `SetupScreen.uitest.tsx` (paste 3 emails → "3 addresses"; the stored rule holds hashes only), `e2e/circle-setup.spec.ts` (create from a pasted list → invite → fresh context joins via OTP → member).

## Exit

An organiser creates a circle from 20 pasted emails, uploads a mark, defines a Speaker badge; a member joining by email OTP gets in with no flight. `npm run verify`, `lint`, `e2e` green; shots of `circles`, `circle`, `circles-new`, `join` in both themes.
